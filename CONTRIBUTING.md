# Участие в разработке

1. Создайте короткую feature-ветку от `develop`.
2. Не изменяйте ядро lsFusion из прикладного репозитория: платформенные изменения
   выполняются в соседнем форке `platform`.
3. Для денежной, правовой или статусной логики добавьте минимальный серверный
   сценарий, который падает без изменения.
4. Выполните сборку и проверки из `docs/RELEASE_CHECKLIST.md`.
5. Откройте pull request в `develop`. В `main` попадают только проверенные релизы.

Коммит не должен содержать `conf/settings.properties`, реальные персональные
данные, пароли, дампы баз, сгенерированные отчёты или журналы приложения.
