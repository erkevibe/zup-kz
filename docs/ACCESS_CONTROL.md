# Доступ к организациям и ролям

## Модель

Пользователь видит данные только тех организаций, которые администратор назначил
ему в форме **Доступ к организациям**. Одна учётная запись может иметь доступ к
одной, нескольким или ни к одной организации. Роль определяет функциональный
контур, а назначение организаций — строки данных внутри этого контура.

Администратор имеет доступ ко всем организациям. Для остальных пользователей
действует единый серверный предикат `organizationAllowed` и его варианты для
изменений и действий. Фильтры форм улучшают интерфейс, но не считаются границей
безопасности.

| Роль | Кадры | Рабочее время | Зарплата | Налоги и отчётность | Изменение данных |
|---|---:|---:|---:|---:|---|
| HR | Да | Нет | Нет | Нет | Кадровые данные доступных организаций |
| Timekeeper | Нет | Да | Нет | Нет | Табели и графики доступных организаций |
| Payroll | Нет | Нет | Да | Справочники законодательства | Расчётные данные доступных организаций |
| Chief accountant | Да | Да | Да | Да | Все контуры доступных организаций |
| Auditor | Да | Да | Да | Да | Только чтение и разрешённые выгрузки |

## Серверные гарантии

- Все организационные формы отфильтрованы по `organizationAllowed`.
- Статусы документов меняются только штатными действиями и только в доступной
  организации.
- Для базовых кадровых данных, личной карточки, графиков, табелей и исходных
  данных расчёта проверяется любое изменение обычных реквизитов, перенос между
  организациями и удаление. Проверяются одновременно прежний и новый владелец.
- Общая карточка физического лица (`Employee`) не дублируется между компаниями:
  её базовые Ф.И.О. и ИИН доступны, если есть хотя бы один договор в разрешённой
  организации. Организационные персональные сведения хранятся в `EmployeeCard`
  и защищаются отдельно.

Автотест создаёт две организации и выполняет негативные изменения от имени HR,
табельщика, расчётчика и главного бухгалтера. Отдельно проверяются чтение,
обычное редактирование черновика, изменение master data, смена владельца,
удаление и обход штатного перехода статуса. Аудитор проверяется как read-only.

## Эксплуатационное ограничение API

В рабочей среде `settings.enableAPI` должен быть выключен, а порт application
server не должен публиковаться во внешнюю сеть. CI временно включает API только
в изолированном контейнере для выполнения тестовых действий.
